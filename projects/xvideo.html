xvideo

X video downloaderTéléchargeur de vidéos Xកម្មវិធីទាញយកវីដេអូ X

The idea

Paste a link. Get the file.

X plays videos inside the post but offers no way to save them. xvideo takes the address of a post — on x.com or twitter.com, web or mobile — finds its video and saves it as an MP4 named after the author and the post, such as USERNAME_POSTID.mp4. A post with several videos gives one file each, _v1, _v2…; a link ending in /video/2 fetches only the second one.

The hard part — talking to X and reading its formats — is done by yt-dlp, the open-source downloader. xvideo adds what a command-line tool needs around it: choosing the right format, safe file names, batches, progress, retries and errors you can read. ffmpeg is optional: X normally serves ready-to-play MP4 files, so ffmpeg is only used to merge separate audio and video streams when a quality is offered only that way, and to embed metadata.

Usage

One link, or a whole list.

# One post
$ xvideo "https://x.com/USERNAME/status/POST_ID"

# Several posts
$ xvideo URL1 URL2 URL3

# From a file: one URL per line, blank lines and # comments are ignored
$ xvideo --file urls.txt
$ cat urls.txt | xvideo --file -

# Output directory (created if needed)
$ xvideo URL --output ./downloads

# At most 720p
$ xvideo URL --quality 720p
OptionWhat it does
--file, -fReads URLs from a file, or from standard input with -. Can be combined with URLs on the command line.
--output, -oOutput directory, created if needed. Default: the current directory.
--quality, -qbest (default), worst, or a maximum resolution: 2160p, 1080p, 720p, 4k…
--overwrite
--skip-existing		Replace an existing file, or leave it and skip the video. By default, the new file gets _1, _2…
--metadata, -mWrites the title, author, date, text and original link into the MP4 (needs ffmpeg).
--quiet
--verbose
--json		Nothing but errors; debug logs and stack traces; or one JSON object per line, for scripts.
--timeout
--retries		Network timeout (30 s by default) and retries on network errors (3 by default, with exponential backoff).
Highlights

Made for long lists.

A batch never stops

A failing URL is reported and the next one starts. The same post listed twice is downloaded once, and a final summary counts what was downloaded, skipped and failed.

Quality with a fallback

A resolution means the short side of the frame, so 720p also matches a vertical 720×1280 video. If the requested one does not exist, xvideo takes the best lower one and says so; if all are higher, the lowest. At equal resolution, a single MP4 is preferred over separate streams.

File names that work everywhere

Characters invalid on Windows, macOS or Linux are replaced; reserved Windows names such as CON and over-long names are handled. An existing file is never overwritten without --overwrite: the new one gets _1, _2… Files of the same run never collide.

Downloads that resume

An interrupted download keeps its .part file and continues where it stopped on the next run, even after Ctrl+C. Network errors, timeouts and server errors are retried with a growing delay; X rate limiting (HTTP 429) is reported, not hammered.

Errors in plain words

Missing post, no video, private account, timeout, disk full, ffmpeg missing… each case has a clear message and a stable code for scripts. Free disk space is checked before the download when the size is known. Stack traces only appear with --verbose.

Metadata without re-encoding

With --metadata, the title, author, date, full text and original link are written into the MP4 tags without re-encoding. The file is rewritten to a temporary copy, then swapped in at once, so an error never leaves a half-written video. Without ffmpeg, the video is still saved, with a warning.

Scope

Public posts only.

xvideo only downloads what anyone can see on X without signing in. It reads no cookies and asks for no credentials, and it has no way around private or protected accounts, age-restricted posts, paywalls, geo-restrictions, rate limits, anti-bot checks or CAPTCHAs. It uses yt-dlp’s default HTTP headers: no User-Agent rotation, no other evasion technique.

Respecting X’s Terms of Service and the copyright of the videos is up to the user: the README asks you to download only videos you have the right to keep, such as your own posts or content whose license allows it. And since X changes its website and API regularly, the first thing to try when extraction stops working is updating yt-dlp: pip install -U yt-dlp.

Le principe

Collez un lien. Récupérez le fichier.

X lit les vidéos dans le post, mais n’offre aucun moyen de les enregistrer. xvideo prend l’adresse d’un post — sur x.com ou twitter.com, version web ou mobile —, trouve sa vidéo et l’enregistre en MP4 sous un nom tiré de l’auteur et du post, comme USERNAME_POSTID.mp4. Un post à plusieurs vidéos donne un fichier par vidéo, _v1, _v2… ; un lien terminé par /video/2 ne récupère que la deuxième.

Le plus délicat — dialoguer avec X et lire ses formats — est confié à yt-dlp, le téléchargeur open source. xvideo ajoute autour ce qu’il faut à un outil en ligne de commande : le choix du bon format, des noms de fichiers sûrs, le traitement par lots, la progression, les nouvelles tentatives et des erreurs lisibles. ffmpeg est facultatif : X fournit normalement des MP4 prêts à lire, et ffmpeg ne sert qu’à fusionner l’audio et la vidéo quand une qualité n’existe qu’en flux séparés, et à intégrer les métadonnées.

Utilisation

Un lien, ou toute une liste.

# Un post
$ xvideo "https://x.com/USERNAME/status/POST_ID"

# Plusieurs posts
$ xvideo URL1 URL2 URL3

# Depuis un fichier : une URL par ligne, lignes vides et commentaires # ignorés
$ xvideo --file urls.txt
$ cat urls.txt | xvideo --file -

# Dossier de sortie (créé si besoin)
$ xvideo URL --output ./downloads

# Au plus 720p
$ xvideo URL --quality 720p

Points forts

Pensé pour les longues listes.

Un lot ne s’arrête jamais

Une URL en échec est signalée, et la suivante démarre. Un même post présent deux fois n’est téléchargé qu’une fois, et un bilan final compte les vidéos téléchargées, ignorées et en échec.

Une qualité avec repli

Une résolution désigne le petit côté de l’image : 720p vaut aussi pour une vidéo verticale en 720×1280. Si la résolution demandée n’existe pas, xvideo prend la meilleure inférieure et le signale ; si toutes sont supérieures, la plus basse. À résolution égale, un MP4 unique est préféré à des flux séparés.

Des noms de fichiers valables partout

Les caractères interdits sous Windows, macOS ou Linux sont remplacés ; les noms réservés de Windows comme CON et les noms trop longs sont gérés. Un fichier existant n’est jamais écrasé sans --overwrite : le nouveau reçoit _1, _2… Les fichiers d’une même exécution n’entrent jamais en collision.

Des téléchargements qui reprennent

Un téléchargement interrompu garde son fichier .part et reprend là où il s’était arrêté à l’exécution suivante, même après un Ctrl+C. Erreurs réseau, délais dépassés et erreurs serveur sont retentés avec une attente croissante ; la limitation de débit de X (HTTP 429) est signalée, sans insister.

Des erreurs en clair

Post introuvable, pas de vidéo, compte privé, délai dépassé, disque plein, ffmpeg absent… chaque cas a un message clair et un code stable pour les scripts. L’espace disque libre est vérifié avant le téléchargement quand la taille est connue. Les piles d’appels n’apparaissent qu’avec --verbose.

Des métadonnées sans réencodage

Avec --metadata, le titre, l’auteur, la date, le texte complet et le lien d’origine sont écrits dans les balises du MP4, sans réencodage. Le fichier est réécrit dans une copie temporaire puis remplacé d’un coup : une erreur ne laisse jamais une vidéo à moitié écrite. Sans ffmpeg, la vidéo est tout de même enregistrée, avec un avertissement.

Périmètre

Posts publics uniquement.

xvideo ne télécharge que ce que tout le monde peut voir sur X sans se connecter. Il ne lit aucun cookie, ne demande aucun identifiant, et n’a aucun moyen de contourner les comptes privés ou protégés, les posts soumis à une limite d’âge, les paywalls, les restrictions géographiques, les limitations de débit, les contrôles anti-robots ou les CAPTCHA. Il utilise les en-têtes HTTP par défaut de yt-dlp : ni rotation de User-Agent, ni autre technique de contournement.

Respecter les conditions d’utilisation de X et le droit d’auteur des vidéos revient à l’utilisateur : le README demande de ne télécharger que les vidéos que l’on a le droit de conserver, comme ses propres posts ou des contenus dont la licence le permet. Et comme X modifie régulièrement son site et son API, la première chose à faire quand l’extraction ne fonctionne plus est de mettre à jour yt-dlp : pip install -U yt-dlp.

Under the hood

How it is built.

cli.pyThe command, built with Typer: options, their validation and the exit codes: 0 when everything was downloaded, 1 when at least one URL failed, 2 for invalid usage, 130 when interrupted.
downloader.pyThe orchestration: URL → post → format → file. It never prints anything and reports its progress as events, so the same code drives the terminal display, --quiet, --json and use as a Python library.
extractor.pyReads the post through yt-dlp, with one session for the whole batch and retries. It asks the server for the exact size of each file, because the bitrates X advertises overestimate sizes 2 to 3 times.
selector.pyTurns the requested quality into a format: one progressive MP4, or separate HLS video and audio streams that ffmpeg merges.
filenames.pyPortable file names and collision-free allocation.
console.pyThe Rich progress bar and console output, and the --quiet and --json modes.
exceptions.pyOne error class per case, each with a plain-language message and the stable code shown in the JSON output.
RequiresPython 3.11 or later. yt-dlp, Typer and Rich are installed automatically; ffmpeg is optional.
Tests186 unit tests with pytest, which need no network access. Ruff for linting and formatting, mypy in strict mode. GitHub Actions runs the tests on Linux, macOS and Windows with Python 3.11 to 3.14.
ReleaseVersion 1.0.0 is published as a GitHub release: a wheel and a source package with SHA-256 checksums, built and published automatically when a version tag is pushed. MIT licence.
Sous le capot

Comment c’est construit.

cli.pyLa commande, construite avec Typer : les options, leur validation et les codes de sortie : 0 quand tout a été téléchargé, 1 quand au moins une URL a échoué, 2 pour une utilisation incorrecte, 130 en cas d’interruption.
downloader.pyL’orchestration : URL → post → format → fichier. Il n’affiche jamais rien et signale sa progression par des événements : le même code sert à l’affichage dans le terminal, à --quiet, à --json et à l’usage comme bibliothèque Python.
extractor.pyLit le post via yt-dlp, avec une seule session pour tout le lot et de nouvelles tentatives. Il demande au serveur la taille exacte de chaque fichier, car les débits annoncés par X surestiment les tailles de 2 à 3 fois.
selector.pyTraduit la qualité demandée en format : un MP4 progressif unique, ou des flux HLS vidéo et audio séparés que ffmpeg fusionne.
filenames.pyNoms de fichiers portables et attribution sans collision.
console.pyLa barre de progression et l’affichage Rich, et les modes --quiet et --json.
exceptions.pyUne classe d’erreur par cas, chacune avec un message en clair et le code stable repris dans la sortie JSON.
PrérequisPython 3.11 ou plus récent. yt-dlp, Typer et Rich s’installent automatiquement ; ffmpeg est facultatif.
Tests186 tests unitaires avec pytest, sans accès au réseau. Ruff pour le lint et le formatage, mypy en mode strict. GitHub Actions lance les tests sous Linux, macOS et Windows, de Python 3.11 à 3.14.
PublicationLa version 1.0.0 est publiée en release GitHub : un wheel et un paquet source avec leurs sommes SHA-256, construits et publiés automatiquement quand un tag de version est poussé. Licence MIT.
ផ្នែកបច្ចេកទេស

របៀបដែលវាត្រូវបានបង្កើត។

cli.pyពាក្យបញ្ជា ដែលបង្កើតដោយ Typer៖ ជម្រើស ការត្រួតពិនិត្យជម្រើស និង exit code៖ 0 នៅពេលទាញយកបានទាំងអស់, 1 នៅពេល URL យ៉ាងហោចណាស់មួយបរាជ័យ, 2 សម្រាប់ការប្រើមិនត្រឹមត្រូវ, 130 នៅពេលត្រូវបានរំខាន។
downloader.pyការសម្របសម្រួលទាំងមូល៖ URL → post → ទម្រង់ → ឯកសារ។ វាមិនបង្ហាញអ្វីទាំងអស់ដោយខ្លួនឯងទេ ប៉ុន្តែរាយការណ៍វឌ្ឍនភាពរបស់វាជា event ដូច្នេះកូដដដែលដំណើរការការបង្ហាញក្នុង terminal, --quiet, --json និងការប្រើជា library Python។
extractor.pyអាន post តាមរយៈ yt-dlp ដោយប្រើ session តែមួយសម្រាប់បាច់ទាំងមូល និងមានការព្យាយាមម្តងទៀត។ វាសួរ server អំពីទំហំពិតប្រាកដនៃឯកសារនីមួយៗ ព្រោះ bitrate ដែល X ប្រកាស ធ្វើឱ្យទំហំប៉ាន់ស្មានធំជាងការពិត 2 ទៅ 3 ដង។
selector.pyបម្លែងគុណភាពដែលបានស្នើទៅជាទម្រង់មួយ៖ MP4 progressive តែមួយ ឬស្ទ្រីម HLS វីដេអូ និងសំឡេងដាច់ដោយឡែក ដែល ffmpeg បញ្ចូលគ្នា។
filenames.pyឈ្មោះឯកសារដែលប្រើបានគ្រប់ប្រព័ន្ធ និងការកំណត់ឈ្មោះដោយមិនជាន់គ្នា។
console.pyរបារវឌ្ឍនភាព និងការបង្ហាញក្នុង console ដោយ Rich ព្រមទាំងរបៀប --quiet និង --json។
exceptions.pyclass កំហុសមួយសម្រាប់ករណីនីមួយៗ ដែលនីមួយៗមានសារជាភាសាសាមញ្ញ និងកូដថេរដែលបង្ហាញក្នុង JSON output។
